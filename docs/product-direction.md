# TARI 产品方向：低频共创的连续故事

> 2026-09-16 用户确认方向调整。本文与新版 technical-roadmap.md 取代旧路线中“Campaign 多 Agent 即时互动优先”的安排。下述产品流程是目标设计；当前已实现边界单独列明。

## 产品承诺

将一本书的世界、人物和冲突转化为可以持续阅读、在关键节点施加影响的故事。LLM 的主要工作是写出有连续性、有节奏的故事；玩家选择关键方向，其影响应当在后续内容中兑现。

主要使用方式是阅读。玩家可以提出方向或在真正有分歧的时刻作决定；暂不参与时，系统可在事先选定的续写策略和生成预算内继续。自动续写必须有停止点，不允许无上限后台生成。尚未选择默认策略时，涉及关键分歧就暂停，不擅自替玩家决定重要关系、牺牲或结局。

Campaign 作为既有实验模式维护兼容，不再是主产品的前置依赖。多 Agent 不作为卖点或固定调用拓扑；后续若分离提纲、写作、检查，先把它们视为有明确输入输出的工作阶段，通过评估决定是否值得增加模型调用。

## 目标体验

1. 导入书籍：识别章节、人物、关系、世界约束、事件时间与出处，可查看编译进度并从失败处继续。
2. 选择阅读起点与介入方式：跟随原著、改变一个关键决定，或以指定人物/身份进入某个阶段。先支持一种清晰的方式，再增加模式。
3. 阅读一个完整场景：有起承转合，不每几句停下来提问；已知关系、此前承诺和玩家方向进入写作上下文。
4. 关键节点介入：明确展现需要玩家决定的分歧，提供少量可理解的方向，也允许自然语言表达意图。普通“继续阅读”不冒充有意义的分支。
5. 继续与重返：保存已发布正文与连续性状态；断线或失败不损坏已完成内容；需要改写历史时创建分支。

“低频”按故事节奏决定，不以固定每 N 句话弹出选项实现。首个可玩样本以 15–30 分钟阅读、少数几个有实际后果的决定为目标，再通过试读调整。

## 三类资料各有职责

| 资料 | 内容 | 权威边界 |
| --- | --- | --- |
| 原著资料 | 带时间、出处的人物/事件/世界信息，区分原文明示与提取推断 | 可核查的原著基线，不自动等同于分支当前状态 |
| 写作计划 | 当前视角、冲突、待兑现承诺、场景目标和介入点 | 可修订草稿，不直接改写存档或原著 |
| 已发布故事 | 正文、已接受的新增情节事实、玩家方向及其后果 | 当前分支的已发生历史，后续创作必须延续 |

玩家改变原著后，新的情节只属于当前故事分支。系统应保留“原著如何发展”和“这个分支已经发生什么”的区别。角色的误解也不能自动升级为世界事实。

新剧情允许创造，不要求把每句文学表达都预先写成状态机。需要结构化的是会影响后续连续性的变化，例如人物位置、关系、承诺、物品与关键事件。运行时能验证归属、引用、版本和允许的变化范围；语义是否自洽还需要写作评估，不能宣称靠类型检查就能证明。

## 生成与发布流程

原著检索及当前分支记忆 → 场景计划 → 正文草稿 → 连续性检查 → 原子发布正文和状态。

- 先做单写手和必要的确定性校验；额外模型检查通过对照评估引入。
- 失败停留在草稿阶段，已发布正文不回退。修改已发布段落须有明确分支/修订操作。
- 检查失败先在同一场景预算内修订，不重新生成全部历史。
- 记录阶段耗时、调用数、token 用量和失败原因。后台生成上限、取消及重试预算属于产品行为。
- 写手读取有界的公开历史与当前允许的知识；不直接读取全书大纲作为玩家此时的事实，防止提前揭示结局。
- 玩家方向可以是全局创作偏好，也可以是一次关键决定。今后须分开建模，不能把两者都当成角色已经执行的动作。

## 当前交付与边界

本轮已实现的第一批基础：

- Story 提交在短数据库事务内检查版本/回合，过期提交抛出冲突，HTTP 返回 409。
- runtime 自行构造选择后果；真实写手返回 NarrativeDraft（正文和诊断），旧式 proposal 必须与 runtime 的结果完全匹配。
- 写手输入包含玩家身份、风格、当前变量与关系、上一段正文、近期公开历史及允许揭示的事实；私有诊断事件不进入该视图。
- 提示词转向完整场景和较低的交互频率，实际文学质量尚需真实模型试读验证。
- 新增 `StoryReader`、`story-read` 和 HTTP `/read`：每次请求发布 1–8 个场景，遇明确决定/结尾提前停止；请求记录与稳定场景 ID 支持失败、取消后的重放恢复。
- 新会话绑定 Bundle 内容摘要，拒绝静默更换素材；关键选择独立记录，自动 continue 不冒充玩家决定。
- 原创《最后一班渡船》提供连续阅读、一次介入与两条后续路线，素材和场景图均在 examples/story。使用方法见 [reading-mode.md](reading-mode.md)。
- 第一轮真实模型试读发现越过选择点、时空冲突与重复描写，叙事质量未通过。已新增可选场景边界和发布前审查，拒绝的草稿不提交；质量结论见 [试读报告](reading-evaluation-2026-09-17.md)。

仍然存在的边界：

- 当前 Bundle 的 beat/choice 合同保持兼容，编译产物通常仍是线性的情节弧；不是已经完成新的场景规划系统。
- freeform 仍不自动改变 beat；已有同步、有预算且可恢复的续写请求，尚无后台调度服务、专用阅读器或动态介入点。
- strict/guided/sandbox 等旧字段没有完整差异化语义，不以其存在宣称相应能力。
- 上下文事实投影限制结构化私有信息，但原始场景文本自身可能包含剧透；场景素材加工与语义评估仍需补齐。
- 重叠请求可能各自花费一次生成，只允许其中一个提交；已提交 request-id 的重放不会再调用写手。请求合并/持久任务占用是下一步工作。
- 故事包来源完整性校验、历史素材文件自动保留和 Campaign 已知可靠性问题仍在待办。素材摘要已绑定新会话；旧无摘要存档需新建会话才能启用连续阅读。

## 成功标准

首个样本必须证明：能够连续阅读；人物行为与此前经历一致；玩家决定能在后续场景中被辨认出来；没有把未发生的计划写成已经发生的历史；重载和分支不会混淆故事。

工程门禁继续验证提交原子性、幂等性、版本一致性、来源及知识边界。体验验收记录重复描写、无因果跳跃、承诺遗忘、剧透和强迫交互，并用固定片段进行对照。编译出的实体数量和 Agent 数量不作为产品质量目标。
