# 仿写模式 | Rewrite Mode

> 一次交互的长篇二次创作。读者说一句"我想看到什么不同"，系统产出一本同量级的长篇。
> 本文定义契约与不变量。故事阅读与自由段见 [freeform-segment.md](freeform-segment.md)。

## 1. 形态

```text
拆书产物（已有：章节卡 / 情节弧 / 世界知识 / 结构大纲）
  + 读者的一句改写方案
  → 同量级长篇（按章可读）
```

**只有一次交互**：读者说出改写方案之后，系统自主完成全书。中途不需要读者参与。
这是把产品收敛到"二次创作"这个确定的领域，用工程手段解决它唯一的硬问题。

### 1.1 面向的问题

LLM 写不了长篇，不是因为写不出好句子，而是因为**漂移**：

- 忘记前文已发生的事，重复或自相矛盾
- 人物性格飘移，行为不再像本人
- 改写前提逐渐失效 —— 写着写着又回到原作轨道
- 伏笔埋了不收，或者收了没埋

## 2. 不变量 | Invariants

1. **改写前提永不丢失**：它写在静态前缀里，每一章都重新送到模型眼前。
2. **偏离必须记账**：任何与原作不同的既定事实进入台账，此后不得被无声推翻。
3. **台账永不压缩**；只有情节摘要可以压缩（这是控制上下文的唯一手段）。
4. **正文是产物，摘要是索引**：后续章节依赖摘要与台账，不依赖全文回溯。
5. **每章独立提交**：中断后可续写，已完成章节不重算。
6. **漂移可检测**：生成后做一致性检查；冲突可解释、可重试。

## 3. 数据模型

```python
class RewriteBrief(BaseModel):
    """读者的那一句话，展开成可执行的创作约束。"""
    instruction: str              # 读者原话，一字不改
    premise: str                  # 提炼出的改写前提
    divergences: list[str]        # 必须改变的点
    invariants: list[str]         # 必须保留的点（人物底色、世界观规则）
    tone: str = ""                # 语体要求（如"古龙风格"）

class LedgerEntry(BaseModel):
    """一条与原作不同、且此后必须成立的既定事实。"""
    entry_id: str
    chapter: int                  # 在第几章确立
    statement: str
    kind: Literal["divergence", "consequence", "character", "relationship", "object", "promise"]

class ChapterSummary(BaseModel):
    chapter: int
    title: str
    summary: str                  # 本章发生了什么，≤300 字
    entries: list[str]            # 本章新增台账条目 id

class ChapterDraft(BaseModel):
    chapter: int
    title: str
    prose: str
    summary: str
    entries: list[LedgerEntry]
```

产物落盘（与编译工作区同构，可续写）：

```text
<workspace>/
  rewrite.json            # brief + 台账 + 已完成章节索引
  chapters/chapter_0001.md
  chapters/chapter_0001.meta.json   # summary + entries
```

## 4. 上下文结构（防漂移的核心）

每章生成时的 prompt 由五段构成，顺序固定：

| 段 | 内容 | 是否变化 |
| --- | --- | --- |
| 静态前缀 | 世界观档案 + 人物 + **改写简报** | 全程不变 |
| 滚动摘要 | 更早章节的压缩摘要（合并在一条里） | 只在压缩时整体重写 |
| 近章全文摘要 | 最近 N 章的逐章摘要 | 追加 |
| **事实台账** | 全部偏离条目，**永不压缩** | 追加 |
| 本章任务 | 原作本章大纲 + 本章要推进到哪 + 目标字数 | 每章 |

**台账位置靠后且完整**：它是模型"不能忘"的那部分。摘要可以糊，台账不能。

### 4.1 压缩策略

当 prompt 超过阈值时，把"近章摘要"中最旧的一批合并进"滚动摘要"（用一次模型调用做压缩）。
台账不参与压缩：条目只增不减。这保证无论写多少章，读者设定的一致性锚点始终在场。

## 5. 逐章循环

```text
for 每一章:
  1. 组装上下文（上表五段）
  2. 生成正文（目标字数）
  3. 提取：本章摘要 + 新增台账条目（结构化输出）
  4. 一致性检查：本章是否违反既有台账 / 是否与本章大纲严重脱节
       - 冲突 → 带冲突说明重试（最多 N 次）
  5. 原子提交：正文 + 元数据 + 台账 + 索引
```

失败停在草稿阶段；已提交章节不回退。

## 6. 漂移的三道防线

| 防线 | 机制 | 检测什么 |
| --- | --- | --- |
| 前提在场 | 静态前缀每章重申改写前提 | "写着写着回到原作轨道" |
| 台账锚定 | 偏离条目完整在场，不可压缩 | "前后矛盾、设定失效" |
| 事后检查 | 生成后一致性核查 | "违反了已经写下的事实" |

三道都失效时，人工可从台账定位到具体章节 —— 这是可审计性的实际价值。

## 7. 与既有代码的关系

| 既有 | 用途 |
| --- | --- |
| `story/decomposer.py` 的章节卡与情节弧 | 本章大纲与全书路线图 |
| `world_knowledge/` 与 `world-info.json` | 静态前缀的世界档案 |
| `narrative/session_context.py` 的规则 | 复用"只追加、不修改"的上下文纪律 |
| 编译器的 manifest 续跑模式 | 每章独立提交、断点续写 |
| 自由段的裁定规则（主持人手册） | 不适用：仿写没有实时裁定，是写作而非主持 |

## 8. 验收标准

1. 一条命令从工作区产出一本按章可读的长篇
2. 每章都体现改写前提（不回到原作轨道）
3. 后章不推翻前章已确立的偏离（台账生效）
4. 中断后可续写，已完成章节不重算
5. 一致性检查能拦下真实冲突，且冲突信息可读
6. 全量门禁通过

## 9. 明确不做

- 不做实时交互（这是本模式存在的理由）
- 不做分支（要另一版就再跑一次，用不同的 brief）
- 不重写编译器
- 不做向量检索（台账 + 摘要足够）

## 10. 用法

```bash
# 先拆书（已有）
trpg story-compile runtime-data/sources/duqing/多情剑客无情剑.md \
  --output-dir runtime-data/story-books/duqing --story-id duqing --lang zh

# 再说一句你想看到什么不同
trpg rewrite runtime-data/story-books/duqing \
  --brief "如果林仙儿一开始就真心爱上阿飞"

# 看进度
trpg rewrite runtime-data/story-books/duqing --status

# 重跑同一条命令 = 从断点续写，已完成章节不重算
# 想扩大范围：--chapters 20   想改每章长度：--words 3000
```

产物：

```text
runtime-data/story-books/duqing-rewrite/
  book.md                           # 成书：目录 + 全部已完成章节，可直接读
  rewrite.json                      # brief + 事实台账 + 进度
  chapters/chapter_0001.md          # 正文，按章可读
  chapters/chapter_0001.meta.json   # 本章摘要 + 新增台账条目
```

每次运行结束都会重写 `book.md`；未写完时它会如实标注 `已完成：N/M 章`。

## 11. 实现记录

### 11.1 世界档案去重（实测发现）

第一版把 `world_knowledge/` 下所有文件都拼进静态前缀，实测 13545 字，
其中 `world_knowledge.md`（6342 字）与 `section_*.md` 内容重复 —— 前者本就是后者的合并版。
改为**合并版优先**，只在其缺失时才逐个读分节。

同时补进**人物关系基线**（原作的 434 条关系取前 120 条）：二次创作改的通常正是这些边，
基线不在场，改写就没有参照物。

调整后：档案 10444 字（含新增的关系段），单章 prompt 由约 9263 tok 降到 7385 tok。
静态前缀只在第一章冷启动时付费，之后命中缓存，因此这部分长度是一次性成本。

### 11.2 目标扩展要写回状态

`--chapters 3` 起步、之后 `--chapters 6` 续写时，`target_chapters` 仍是 3，
进度显示成 `6/3`。现在 `run()` 会在实际章节数更多时写回目标。
（这条是被端到端实跑暴露的，测试里补了 `test_widening_the_target_updates_state`。）

### 11.3 失败也要落盘

`run()` 原先只在成功时保存状态，导致一章耗尽重试后的失败记录丢失，
续跑时会重算同一章。改为 `finally` 落盘：失败记录与已增长的台账都属于可恢复状态。

## 12. 尚未验证的部分

（本节在真实模型恢复后应重新评估）

- **真实模型下的漂移表现**：三道防线（前提在场 / 台账锚定 / 事后检查）是按机制验证的，
  真实长文的漂移率尚未测量。落地时的第一件事应当是：跑 10 章，人工核对台账遵守率。
- **每章字数控制**：提示词给了目标字数，但没有硬约束；真实模型可能明显短于或长于目标。
- **一致性检查的误报率**：Fake 只能验证机制通断，真实模型可能过度拒绝或放行。
- **压缩质量**：滚动摘要由模型生成，压缩后的梗概是否保住因果链，需要真实样本判断。
