## 当前基线

- source import、可恢复语义编译、StoryBundle、Story 会话/选择/分支/CLI/HTTP 已有实现。
- Campaign CLI/Web/多 Agent 路径保留，停止新增多 Actor、规则市场及即时互动能力。
- SQLite 生命周期与 LLM transport 共享，Story/Campaign 领域状态仍独立。
- 自动编译的可玩内容通常还是线性情节弧；现已支持沿场景图的有限连续阅读与明确介入点，动态场景规划与专用阅读器尚未交付。
- 历史真实 LLM 编译结果是有用证据，但不代替新体验的真实模型评估。

## S0：可信的 Story 写作基础 — 进行中

本轮已实现，尚未提交：

- 旧快照预检查 + 提交事务内 version/turn 校验；HTTP 冲突为 409。
- runtime 确定选择 effects/reveal/target/source refs；真实 author 仅输出正文。
- 旧 author proposal 兼容校验，拒绝重复/遗漏效果、变造引用和遗漏揭示。
- 身份、关系、公开历史和可见事实进入写手上下文。
- 两个独立 store/runtime 的重叠生成及 HTTP 重叠请求回归。
- 新会话绑定 Bundle 内容摘要；同一故事 ID 下更换素材也会被拒绝。
- 连续阅读请求持久化，覆盖生成失败、取消、场景已提交但最终报告未写入等恢复路径。

剩余任务：

1. 在已绑定素材摘要的基础上，提供历史故事包保留与明确的旧存档迁移策略。
2. 校验编译 Bundle 的来源引用，显式区分原著 evidence、外部引用与生成内容；保留手工资源的兼容策略。
3. 固化离线 CI；真实 LLM E2E 保持 opt-in，不能要求开发者提供密钥才能运行常规测试。
4. 以实际场景矩阵而非重复次数凑数，补齐中断、恢复、重复请求和缓存失效报告。

出口：Story 已发布内容在重试、重叠提交、素材变更和恢复后保持一致；错误可解释；所有本地门禁通过。

## S1：从原著资料到可写场景

目标：让编译产物支持持续创作，而不止复述情节摘要。

- 原著知识保留出处与时间，区分事实、角色信念和提取推断。
- 提供一个明确的起始场景：人物目标、当前冲突、可见信息和不可提前揭示的信息。
- 写作计划描述下一场景的因果承接及必要介入点；计划与已发布历史分离。
- 先围绕一个短篇片段验证，不预生成整本书所有分支，不先引入向量数据库。
- 创作可引入分支新事实，但不能无痕改写原著基线或此前已发布事实。

出口：同一原著片段可产生两种可辨认的故事走向；角色、关系和关键事实连贯；来源与新增情节可区分。

## S2：场景续写与连续性

已交付初版：`StoryReader` / `story-read` / HTTP `/read`，1–8 场景预算、显式决定处暂停、相同请求恢复、关键选择记忆。原创《最后一班渡船》包含一次介入与两条后续路线。当前没有后台调度，场景图仍由素材作者提供。

- 明确“阅读偏好”“关键决定”“继续阅读”三种输入，不要求用户每段都扮演一次行动。
- 生成完整场景，维护必要的事件/关系/承诺记忆，控制上下文长度。
- 草稿经过检查后，正文与连续性变化原子发布；修订在有限预算内进行。
- 自动续写具备明确上限、取消、恢复和停止点；未授权关键决定必须等待玩家。
- 新 generation job 合并相同请求或持有持久占用，减少重叠生成成本；数据库提交校验继续兜底。

出口：一个 15–30 分钟样本可连贯阅读，只有少数有意义的介入点；断线后能找到同一任务及已发布进度。

## S3：阅读与介入界面

- 专用阅读界面：书源/起点选择、正文、生成进度、关键方向选择、暂停续写、重载及分支。
- 用户界面展示创作意图和故事后果；内部 provider、checkpoint、typed protocol 留在诊断界面。
- 随真实需求拆分 Web routes/application services，保留原 CLI/HTTP 兼容入口。
- 上线公共访问前完成认证、ownership、请求限制及秘密过滤；本地原型不提前建设多租户平台。

出口：用户可无需 CLI 完成导入后的首个阅读样本，并辨认一次介入带来的后果。

## S4：质量与成本迭代

第一轮真实试读已完成：8 场景，工程状态正确，但正文提前替玩家选择、重复描写并出现连续性冲突，质量未通过。已据此增加显式场景边界和发布前审查；审查模型本身仍可能误判。详情见 [试读报告](reading-evaluation-2026-09-17.md)。

- 固定故事片段对照：连续性、文风、节奏、剧透、重复、选择后果和读完意愿。
- 测量阶段耗时、token、模型调用数、失败与修订率；本轮尚无新流程的真实模型基准。
- 对比单写手与附加规划/检查阶段，只有收益得到证实时才增加模型角色。
- 通过资料检索和记忆压缩控制成本；不以增加 Agent、实体或世界书条目数量证明质量。

## 不变的工程门禁

运行时拥有提交、版本和分支权威；模型不能直接写库。两个领域状态不合并。外部接口只负责输入、资源解析和错误映射。

```bash
.venv/bin/python -m pytest -q
.venv/bin/ruff check .
.venv/bin/mypy src
.venv/bin/python -m compileall -q src tests
git diff --check
```

新增文件通过 Ruff format。格式清理限定在必要范围，避免顺手重排历史文件。真实编译还须验证 manifest、正式 loader、来源和缓存续跑；不得将密钥或私有运行环境写入库。
